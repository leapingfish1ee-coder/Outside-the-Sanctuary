# Outside the Sanctuary — Graphic Design Guideline

版本：2.0
范围：游戏 HUD、Wiki、项目展示页、静态图形与后续视觉资产。
上游方法参考：emilkowalski/skills @ e8a175de22ae1e49370fc144c1f3bb9aeedf988d（MIT）。

现行参数以 [BrandDesignGuideline](BrandDesignGuideline.md) 及 `styles/brand.css`、`styles/hud.css`、`styles/wiki.css` 为准。下文保留原始视觉原则与历史尺度；排版参数、响应式、面额按钮、技能空槽与日志旧描述由新规范对应章节替代。黑白、宋体、细线、语义色和原创资产约束继续有效。

## 1. 核心设计命题

本项目的视觉目标不是“华丽奇幻 UI”，而是“极简平面设计中的游戏信息系统”：大量空白、纸面感、克制线条、明确层级、少量语义色，使界面像被印刷在白色档案纸上的战斗仪表。

关键词：
- 白场。
- 宋体。
- 黑白。
- 细线。
- 信息密度局部集中。
- 颜色只用于语义。
- 游戏性来自结构，不来自装饰。
- 仪表感与出版物感并存。

## 2. 构图系统

### 2.1 主画面视觉轴

桌面端形成三条主要轴：
- 左轴：标题 → 玩家身份 → 属性面板。
- 中轴：顶部敌人状态 → 主留白 → 底部技能栏。
- 右轴：Wiki 等全局入口。

左轴是角色自身信息，中轴是战斗对象与操作，右轴是系统级导航；新增元素必须先判断属于哪条轴，禁止随意悬浮。

### 2.2 留白

1920px 宽桌面目前使用约 4.1667vw 左右安全边距，相当于 80px；这是主视觉尺度，不应被 16px/24px 的常规 Web 页边距替代。

大面积空白是设计元素，不要因为“看起来空”而自动填充背景纹理、面板或插图。

### 2.3 分组

优先级：
1. 空间距离。
2. 1px 分隔线。
3. 字体大小/字重。
4. 灰度。
5. 语义色。

除技能栏等明确控件集合外，不要用厚边框或卡片背景制造分组。

## 3. 字体系统

### 3.1 字体角色

宋体栈：
"Songti SC", SimSun, "宋体", serif

使用范围：
- 项目标题。
- 玩家角色名。
- 属性名称与数值。
- Wiki 正文标题与核心内容。
- 职业等世界观名词。

黑体栈：
SimHei, "黑体", sans-serif

使用范围：
- 副标题。
- 标签。
- 元数据。
- 百分比。
- 键位与辅助说明。
- Wiki 导航提示。

### 3.2 当前关键字号

- 项目标题：42px 桌面，32px 窄屏。
- 副标题：18px 桌面，15px 窄屏。
- 玩家角色名：23px。
- 玩家职业：18px。
- 属性名称/值：30px。
- 自由点数：24px。
- 敌人名称/百分比：12px。
- Wiki 页面 H1：46px，移动端 38px。
- Wiki 表格职业名：17px。
- Wiki 辅助组合标签：10px。

新增字号应尽量从这些层级中取值，不要无理由增加 13px、15px、19px、21px 等平行层级。

## 4. 颜色系统

### 4.1 中性色

- 页面背景：#FFFFFF。
- 主文本/主边框：#111111 或 #000000。
- 次信息：#777777–#999999。
- 弱分隔：#D7D7D7–#EDEDED。
- 极浅底色：#FAFAFA，只用于少量结构强调。

### 4.2 六属性语义色

- 力量：#D64B4B。
- 敏捷：#33C47A。
- 智力：#5C6BFF。
- 意志：#3FC7D6。
- 灵知：#D8A03A。
- 信仰：#C8D2D2 / 极浅灰青。

属性名允许从语义色渐变至黑色，以保持已建立的 SVG/页面语言；除此之外，颜色应以点、线、小面积填充出现。

### 4.3 血条

敌人血条允许从暗红语义色过渡到黑色；血量状态不得使用高饱和荧光红，也不使用厚重 RPG 纹理框。

## 5. 线、边框与阴影

- 默认边框：1px。
- 主边框：#111。
- 次分隔：#BDBDBD / #D7D7D7。
- 默认圆角：0。
- 小圆点或真正语义为“点”的元素可用 50% 圆角。
- 技能栏允许非常轻的投影，用于从白色背景中分离控件组；阴影必须近乎不可察觉。
- 禁止“大圆角 + 阴影 + 白卡片”的 SaaS 组合。

## 6. HUD 组件规范

### 6.1 品牌区

标题固定在左上主安全边距；副标题紧随其下；标题区与角色信息区通过空间和细线分隔，不能与角色身份混成一个标题块。

### 6.2 玩家身份区

与属性面板属于同一左侧 HUD 组：
- 与属性面板共享左对齐线和整体宽度。
- “角色名 / 职业”为标签—值结构。
- 标签用灰色小黑体，值用宋体。
- 玩家信息不得被设计成头像卡片，除非后续游戏系统真的需要头像语义。

### 6.3 属性面板

结构来源于项目原始 SVG：
- 自由点数为总览头。
- 六项属性垂直排列。
- 属性名使用六属性语义渐变。
- 数值为黑色。
- +1 / +5 / +10 / +50 / +100 为弱灰辅助操作。
- 每行用细横线收束，不使用方框包裹。

任何未来属性扩展都应先尊重 SVG 的字形、基线、线条和密度关系。

### 6.4 敌人状态

顶部居中垂直列出：
- 名称左，百分比右。
- 细血条。
- 单个条目保持紧凑。
- 多敌人时保持固定间距，不扩展成卡片。

### 6.5 技能栏

- 底部居中。
- 以紧凑方格为基本单元。
- 键位提示小且弱。
- 图标采用原创抽象几何、1px 线条与六属性色少量点缀。
- 可借鉴 MMORPG 动作栏“连续槽位 + 键位映射”的交互结构。
- 禁止复制《魔兽世界》或其他商业游戏的技能图标、框体纹理、职业徽标、字体或专有视觉资产。

## 7. Wiki 规范

Wiki 是“项目档案”，不是营销站：
- 左侧固定/粘性导航。
- 右侧正文。
- 用表格表达组合关系。
- 用排版层级表达章节。
- 允许水平滚动的大表格，但必须保持可读的列头和第一列语义。
- 不把每个职业做成卡片。
- 纯系职业允许用 #FAFAFA 轻底色标记。
- 世界观名词保持朴素、功能性命名，尤其一阶职业代表新手与基层劳动者。

## 8. 图标与平面资产

### 8.1 图标

默认图标语言：
- 单色或单一语义色。
- 1px–1.5px 描边。
- 几何、符号化、非拟物。
- 在 16–52px 尺度仍可辨认。
- 不使用 emoji 作为正式图标。

### 8.2 插图/海报

如果以后加入大图：
- 图像不能填满所有留白。
- 图像应作为“事件/地点/人物”的内容，而非背景装饰。
- 图片旁的文字仍遵守宋体/黑体分工。
- 允许黑白照片、扫描感、版画感，但禁止默认套用赛博霓虹或游戏商城风。

## 9. 动画与交互

设计原则来自上游技能但按本项目收敛：

### 9.1 是否动画

先判断频率：
- 高频 HUD 操作：尽量无动画。
- 按钮按下：允许 100–160ms 的轻缩放反馈。
- Wiki 导航：颜色/背景快速变化即可。
- 弹窗、抽屉等偶发界面：才允许更完整的进入退出动画。

### 9.2 曲线和属性

- 进入/退出：强响应 ease-out。
- 屏幕内移动：ease-in-out。
- 持续运动：linear。
- 默认 UI 动画小于 300ms。
- 主要动画属性限定为 transform 与 opacity；clip-path 可用于明确的遮罩效果。
- 禁止 transition: all。
- 禁止 scale(0) 入场。
- 高频键盘操作不加装饰动画。

### 9.3 无障碍

- prefers-reduced-motion 下移除明显位移和缩放，保留必要的透明度/颜色反馈。
- hover 样式只在 (hover: hover) and (pointer: fine) 条件下出现。
- focus-visible 必须可见。

## 10. 响应式

现有断点：
- 约 1100px：缩小左侧属性与技能栏，收紧边距。
- 760px 以下：标题、玩家区、敌人区重新错位避免重叠，技能栏固定底部并可横向滚动。

新增组件必须验证：
- 1920×1080。
- 1366×768。
- 1100px 附近。
- 760px。
- 320px。
- 200% 浏览器缩放。

移动端新增全屏/固定布局时：
- 需要动态高度时用 dvh。
- 首屏需要稳定不溢出时用 svh。
- 不禁用 pinch zoom。
- 触控按钮不得只依赖 hover。
- 固定底栏若进入刘海/底部手势区域，需要安全区适配。

## 11. 文案和命名视觉原则

- 一阶职业：基层、学徒、普通劳动者，命名务实，例如搬运工、民兵、抄写员、矿工、农夫、侍僧。
- 高阶职业未来可以逐层增加抽象度与仪式感，但每一阶必须明显比前一阶更专业。
- 不使用为了“酷”而无功能含义的生造词。
- 敌人占位名在原型阶段可用编号；进入内容设计阶段必须换成世界观内实体名。

## 12. 设计审查清单

提交 UI 前逐项检查：
- 是否保留足够白场。
- 是否沿用现有左/中/右视觉轴。
- 是否使用了正确字体角色。
- 是否新增了无必要的圆角、阴影或背景块。
- 六属性色是否仍只承担语义。
- 信息层级是否主要靠排版与细线，而非卡片。
- 320px 和 200% 缩放是否仍能访问核心内容。
- 长角色名、长职业名、大数值是否破坏布局。
- 点击/触控是否有反馈。
- 动画是否有明确功能目的。
- 是否避免复制第三方游戏受版权保护的视觉资产。
